* Addendum: Comprehensive Arch Linux Hardening Guide for Production Use
:PROPERTIES:
:CUSTOM_ID: addendum-comprehensive-arch-linux-hardening-guide-for-production-use
:END:
This guide provides comprehensive security hardening procedures for Arch
Linux systems intended for production use. The Arch Wiki notes that you
can never make a system 100% secure unless you unplug the machine from
all networks, turn it off, lock it in a safe, smother it in concrete and
never use it - but we can significantly improve security through defense
in depth.

*⚠️ WARNING:* This guide assumes you have good Linux knowledge. Hardening
can make your system difficult to use if misconfigured. Always test
changes in a non-production environment first.

** Security Principles
:PROPERTIES:
:CUSTOM_ID: security-principles
:END:
1. *Principle of Least Privilege* - Each part of a system should only
   access what is strictly required
2. *Defense in Depth* - Multiple independent layers of security
3. *Minimize Attack Surface* - Disable/remove unnecessary services
4. *Stay Updated* - Promptly install security patches
5. *Paranoia Helps* - Be suspicious of anything too good to be true
6. *Prepare for Failure* - Have incident response plans

** Part 1: Kernel Hardening
:PROPERTIES:
:CUSTOM_ID: part-1-kernel-hardening
:END:
*** 1.1 Kernel Parameters (Sysctl)
:PROPERTIES:
:CUSTOM_ID: kernel-parameters-sysctl
:END:
Create =/etc/sysctl.d/99-security.conf=:

#+begin_src sh
sudo nvim /etc/sysctl.d/99-security.conf
#+end_src

Add these security-focused kernel parameters:

#+begin_src ini
# Kernel hardening
# Hide kernel pointers from regular users (mitigates kernel exploits)
kernel.kptr_restrict=2

# Restrict access to kernel logs
kernel.dmesg_restrict=1

# Disable kexec (prevents replacing running kernel)
kernel.kexec_load_disabled=1

# Restrict access to performance events
kernel.perf_event_paranoid=3

# Prevent kernel from loading non-signed modules (if using signed modules)
# kernel.modules_disabled=1  # CAUTION: Can't load ANY modules after boot

# Restrict BPF JIT compiler (used in some kernel exploits)
net.core.bpf_jit_harden=2

# Restrict unprivileged use of BPF
kernel.unprivileged_bpf_disabled=1

# Disable unprivileged user namespaces (reduces attack surface)
kernel.unprivileged_userns_clone=0

# Restrict ptrace to parent processes only
kernel.yama.ptrace_scope=2

# Disable core dumps (may contain sensitive info)
kernel.core_pattern=|/bin/false
fs.suid_dumpable=0

# Network hardening
# Ignore ICMP redirects
net.ipv4.conf.all.accept_redirects=0
net.ipv4.conf.default.accept_redirects=0
net.ipv6.conf.all.accept_redirects=0
net.ipv6.conf.default.accept_redirects=0

# Ignore send redirects
net.ipv4.conf.all.send_redirects=0
net.ipv4.conf.default.send_redirects=0

# Reverse path filtering (anti-spoofing)
net.ipv4.conf.all.rp_filter=1
net.ipv4.conf.default.rp_filter=1

# Don't accept source routing
net.ipv4.conf.all.accept_source_route=0
net.ipv4.conf.default.accept_source_route=0
net.ipv6.conf.all.accept_source_route=0
net.ipv6.conf.default.accept_source_route=0

# Ignore ICMP ping requests (optional, breaks some network diagnostics)
# net.ipv4.icmp_echo_ignore_all=1
# net.ipv6.icmp.echo_ignore_all=1

# Log martian packets
net.ipv4.conf.all.log_martians=1
net.ipv4.conf.default.log_martians=1

# Protect against TCP SYN flood attacks
net.ipv4.tcp_syncookies=1
net.ipv4.tcp_syn_retries=2
net.ipv4.tcp_synack_retries=2
net.ipv4.tcp_max_syn_backlog=4096

# Disable IPv6 if not needed (reduces attack surface)
# net.ipv6.conf.all.disable_ipv6=1
# net.ipv6.conf.default.disable_ipv6=1
#+end_src

Apply settings:

#+begin_src sh
sudo sysctl --system

# Verify
sudo sysctl -a | grep -E 'kptr_restrict|dmesg_restrict|ptrace_scope'
#+end_src

*** 1.2 Boot Parameters
:PROPERTIES:
:CUSTOM_ID: boot-parameters
:END:

#+begin_src sh

#+end_src

Add these security-focused kernel parameters:

#+begin_src sh
# Add to KERNEL_CMDLINE[default]+= lines

# Enable kernel lockdown (integrity mode)
KERNEL_CMDLINE[default]+="lockdown=integrity"
# OR for maximum security (confidentiality mode):
# KERNEL_CMDLINE[default]+="lockdown=confidentiality"

# Disable Intel/AMD CPU vulnerabilities mitigations bypass
# (ensures all mitigations are active)
KERNEL_CMDLINE[default]+="mitigations=auto,nosmt"

# Disable vsyscall (legacy interface with security issues)
KERNEL_CMDLINE[default]+="vsyscall=none"

# Enable page table isolation (Meltdown mitigation)
KERNEL_CMDLINE[default]+="pti=on"

# Randomize kernel memory
KERNEL_CMDLINE[default]+="init_on_alloc=1 init_on_free=1"

# Enable CPU vulnerability mitigations
KERNEL_CMDLINE[default]+="spec_store_bypass_disable=on"
KERNEL_CMDLINE[default]+="spectre_v2=on"

# Disable legacy 32-bit syscalls (if not needed)
# KERNEL_CMDLINE[default]+="ia32_emulation=0"

# Module signing enforcement
KERNEL_CMDLINE[default]+="module.sig_enforce=1"
#+end_src

Apply and regenerate initramfs:

sudo reboot
#+end_src

** Part 2: Filesystem Hardening

*** 2.1 Secure /tmp, /var/tmp, /dev/shm
:PROPERTIES:
:CUSTOM_ID: secure-tmp-vartmp-devshm
:END:
Edit =/etc/fstab= and add/modify these entries:

#+begin_src sh
sudo nvim /etc/fstab
#+end_src

Add these mount options:

#+begin_src fstab
# Secure /tmp
tmpfs   /tmp    tmpfs   rw,nodev,nosuid,noexec,mode=1777   0 0

# Secure /var/tmp (bind mount to /tmp)
/tmp    /var/tmp    none    bind,nodev,nosuid,noexec   0 0

# Secure /dev/shm
tmpfs   /dev/shm    tmpfs   rw,nodev,nosuid,noexec,mode=1777   0 0
#+end_src

Apply (after backup):

#+begin_src sh
# Backup current fstab
sudo cp /etc/fstab /etc/fstab.backup

# Test mount
sudo mount -o remount /tmp
sudo mount -o remount /dev/shm

# Verify
mount | grep -E 'tmp|shm'
#+end_src

*Note:* =noexec= on /tmp may break some package installations. If issues
arise, temporarily remount with exec:

#+begin_src sh
sudo mount -o remount,exec /tmp
# Run installation
sudo mount -o remount,noexec /tmp
#+end_src

*** 2.2 Hide Process Information
:PROPERTIES:
:CUSTOM_ID: hide-process-information
:END:
The Arch Wiki recommends hiding other users' processes. Edit
=/etc/fstab=:

#+begin_src sh
# Hide processes from other users (except wheel group)
proc    /proc   proc    nosuid,nodev,noexec,hidepid=2,gid=wheel   0 0
#+end_src

This prevents users from seeing processes of other users.

*** 2.3 Audit Filesystem Permissions
:PROPERTIES:
:CUSTOM_ID: audit-filesystem-permissions
:END:
#+begin_src sh
# Find world-writable files
sudo find / -xdev -type f -perm -002 -ls 2>/dev/null

# Find files with no owner
sudo find / -xdev -nouser -o -nogroup 2>/dev/null

# Find SUID/SGID files (potential privilege escalation)
sudo find / -xdev \( -perm -4000 -o -perm -2000 \) -type f -ls 2>/dev/null

# Review and remove unnecessary SUID bits
# sudo chmod u-s /path/to/file
#+end_src

*** 3.3 Secure Sudo Configuration

:CUSTOM_ID: secure-sudo-configuration

#+end_src

Add these security-focused directives:

#+begin_src sudoers
# Require password for sudo (even shortly after last sudo)
Defaults timestamp_timeout=0

# OR: Reasonable timeout (15 minutes)
# Defaults timestamp_timeout=15

# Require password for ALL commands (no NOPASSWD except where absolutely needed)
# Remove or comment any NOPASSWD entries

# Log all sudo commands
Defaults log_output
Defaults!/usr/bin/sudoreplay !log_output
Defaults!/sbin/reboot !log_output

# Use strong password hashing
Defaults passwd_timeout=1

# Require root password instead of user password (more secure)
# Defaults rootpw

# Secure PATH
Defaults secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"

# Don't allow shell escapes
Defaults noexec

# Enable logging
Defaults logfile="/var/log/sudo.log"
Defaults log_year, log_host, log_input, log_output
#+end_src

*** 4.1 SSH Server Configuration
:PROPERTIES:
:CUSTOM_ID: ssh-server-configuration
:END:
Edit =/etc/ssh/sshd_config=:

#+begin_src sh
sudo nvim /etc/ssh/sshd_config
#+end_src

Apply these security settings:

#+begin_src sshconfig
# Change default port (security through obscurity, but helps with automated attacks)
Port 2222

# Only listen on specific IP (if applicable)
# ListenAddress 192.168.1.10

# Protocol 2 only (v1 is deprecated and insecure)
Protocol 2

# Disable root login
PermitRootLogin no

# Only allow specific users
AllowUsers your_username

# OR only allow specific groups
# AllowGroups ssh-users

# Disable password authentication (use keys only)
PasswordAuthentication no
PermitEmptyPasswords no
ChallengeResponseAuthentication no

# Enable public key authentication
PubkeyAuthentication yes
AuthorizedKeysFile .ssh/authorized_keys

# Disable dangerous features
X11Forwarding no
PermitTunnel no
AllowAgentForwarding no
AllowTcpForwarding no
PermitUserEnvironment no

# Use strong ciphers and MACs
Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes192-ctr,aes128-ctr
MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com,hmac-sha2-512,hmac-sha2-256
KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org,diffie-hellman-group-exchange-sha256

# Use strong host keys
HostKey /etc/ssh/ssh_host_ed25519_key
HostKey /etc/ssh/ssh_host_rsa_key

# Connection timeout
ClientAliveInterval 300
ClientAliveCountMax 2

# Login grace time
LoginGraceTime 60

# Max authentication attempts
MaxAuthTries 3

# Max concurrent sessions
MaxSessions 2

# Enable verbose logging
LogLevel VERBOSE

# Use privilege separation
UsePrivilegeSeparation sandbox

# Disable host-based authentication
HostbasedAuthentication no
IgnoreRhosts yes

# Disable unused features
GatewayPorts no
PermitUserRC no
#+end_src

Regenerate SSH host keys with stronger algorithms:

#+begin_src sh
# Remove old keys
sudo rm /etc/ssh/ssh_host_*

# Generate new strong keys
sudo ssh-keygen -t ed25519 -f /etc/ssh/ssh_host_ed25519_key -N ""
sudo ssh-keygen -t rsa -b 4096 -f /etc/ssh/ssh_host_rsa_key -N ""

# Set correct permissions
sudo chmod 600 /etc/ssh/ssh_host_*_key
sudo chmod 644 /etc/ssh/ssh_host_*_key.pub

# Restart SSH
sudo systemctl restart sshd.service
#+end_src

*** 4.2 Setup Fail2Ban for SSH
:PROPERTIES:
:CUSTOM_ID: setup-fail2ban-for-ssh
:END:
Install and configure fail2ban:

#+begin_src sh
sudo pacman -S fail2ban

# Copy paths configuration
sudo cp /etc/fail2ban/paths-fedora.conf /etc/fail2ban/paths-archlinux.conf

# Create jail configuration
sudo nvim /etc/fail2ban/jail.local
#+end_src

Add SSH jail configuration:

#+begin_src ini
[DEFAULT]
# Ban for 2 weeks
bantime = 2w

# Find failures over 1 day
findtime = 1d

# IPs that should never be banned (your trusted IPs)
ignoreip = 127.0.0.1/8 ::1 YOUR_TRUSTED_IP

[sshd]
enabled = true
filter = sshd
backend = systemd
maxretry = 3
banaction = nftables[type=multiport]
# If using custom SSH port
port = 2222
#+end_src

Enable and start:

#+begin_src sh
sudo systemctl enable --now fail2ban.service

# Check status
sudo fail2ban-client status sshd
#+end_src

*** 7.1 Install and Configure Auditd
:PROPERTIES:
:CUSTOM_ID: install-and-configure-auditd
:END:
#+begin_src sh
sudo pacman -S audit

# Enable and start
sudo systemctl enable --now auditd.service

# Add audit rules
sudo nvim /etc/audit/rules.d/audit.rules
#+end_src

Add these audit rules:

#+begin_src sh
# Delete all existing rules
-D

# Buffer size
-b 8192

# Failure mode (0=silent 1=printk 2=panic)
-f 1

# Audit system calls
-a always,exit -F arch=b64 -S execve -k exec
-a always,exit -F arch=b32 -S execve -k exec

# Monitor password file changes
-w /etc/passwd -p wa -k passwd_changes
-w /etc/group -p wa -k group_changes
-w /etc/shadow -p wa -k shadow_changes
-w /etc/gshadow -p wa -k gshadow_changes

# Monitor sudo usage
-w /etc/sudoers -p wa -k sudoers_changes
-w /etc/sudoers.d/ -p wa -k sudoers_changes

# Monitor SSH configuration
-w /etc/ssh/sshd_config -p wa -k sshd_config_changes

# Monitor kernel module loading
-w /sbin/insmod -p x -k module_insertion
-w /sbin/modprobe -p x -k module_insertion
-w /sbin/rmmod -p x -k module_removal

# Monitor file deletion by users
-a always,exit -F arch=b64 -S unlink -S unlinkat -S rename -S renameat -F auid>=1000 -F auid!=4294967295 -k delete

# Monitor changes to time
-a always,exit -F arch=b64 -S adjtimex -S settimeofday -k time_change

# Make configuration immutable
-e 2
#+end_src

Reload rules:

#+begin_src sh
sudo augenrules --load

# View audit logs
sudo ausearch -k passwd_changes
sudo aureport --summary
#+end_src

** Part 8: Systemd Service Hardening
:PROPERTIES:
:CUSTOM_ID: part-8-systemd-service-hardening
:END:
For each systemd service, add security directives. Example for a custom
service:

#+begin_src sh
sudo systemctl edit your-service.service
#+end_src

Add these hardening options:

#+begin_src ini
[Service]
# Filesystem isolation
ProtectSystem=strict
ProtectHome=true
ReadOnlyPaths=/
ReadWritePaths=/var/lib/your-service

# Prevent access to other users' data
PrivateTmp=yes
PrivateDevices=yes

# Network isolation (if service doesn't need network)
PrivateNetwork=yes
# OR restrict to localhost only
# IPAddressDeny=any
# IPAddressAllow=localhost

# System call filtering
SystemCallFilter=@system-service
SystemCallFilter=~@privileged @resources

# No new privileges
NoNewPrivileges=yes

# Restrict namespaces
RestrictNamespaces=yes

# Restrict realtime
RestrictRealtime=yes

# Protect kernel modules
ProtectKernelModules=yes

# Protect kernel tunables
ProtectKernelTunables=yes

# Protect kernel logs
ProtectKernelLogs=yes

# Protect clock
ProtectClock=yes

# Protect hostname
ProtectHostname=yes

# Restrict SUID/SGID
RestrictSUIDSGID=yes

# Remove capabilities
CapabilityBoundingSet=
# OR limit to specific caps needed
# CapabilityBoundingSet=CAP_NET_BIND_SERVICE

# Lock down personality
LockPersonality=yes

# Memory deny write-execute
MemoryDenyWriteExecute=yes

# Restrict address families
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
#+end_src

Analyze service security:

#+begin_src sh
systemd-analyze security your-service.service
#+end_src

** Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:
Production hardening is an ongoing process, not a one-time task:

1. ✅ *Kernel hardening* - Sysctl and boot parameters
2. ✅ *Filesystem security* - Secure mount options
3. ✅ *Access control* - Strong passwords, sudo restrictions
4. ✅ *SSH hardening* - Key-based auth, fail2ban
5. ✅ *Firewall* - Restrictive rules, rate limiting
6. ✅ *MAC* - AppArmor for application confinement
7. ✅ *Audit* - System monitoring and logging
8. ✅ *Updates* - Automated security patching
9. ✅ *Backups* - Regular tested backups
10. ✅ *Documentation* - Maintain security documentation

*Remember:* Security is a balance between protection and usability.
Over-hardening can make systems unusable. Test all changes thoroughly
before production deployment!

*Final Note:* This guide provides a strong security baseline. Always
stay informed about new vulnerabilities and adapt your security measures
accordingly. Subscribe to: - Arch Security Tracker - Arch security
mailing list - CVE notifications for your critical software
