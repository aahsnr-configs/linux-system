§ 1

Hardware & Drive Layout

Two of the three guides target the same dual-NVMe machine. The README is the outlier — it is a laptop (ASUS ROG Zephyrus) with a single drive and NVIDIA GPU. Your new guide needs to decide which hardware profile it targets before anything else.

arch_hardening_setup.md

2× NVMe: nvme0n1 500 GB + nvme1n1 1 TB

CPU: Intel i9-13900K (Raptor Lake). Intel-specific features discussed: TME, VT-d, CET, RDRAND, Thunderbolt 4. No GPU. Workstation-class, no display output configured.

gentoo-setup.md

2× NVMe: nvme1n1 500 GB (boot disk) + nvme0n1 1 TB (data disk)

No CPU discussion beyond cpuid2cpuflags for compiler flags. NVIDIA driver installation briefly noted in kernel section. Same hardware profile as Arch file.

README.md (personal)

1× NVMe only: nvme0n1

ASUS ROG Zephyrus laptop (hostname: zephyrus). ASUS-specific kernel modules needed. NVIDIA GPU with full driver stack. HiDPI display (1.75× scale). Laptop-specific power management services.

lsblk — actual output embedded in README
nvme0n1
├─nvme0n1p1   # EFI / boot
└─nvme0n1p2   # LUKS partition
  └─cryptlvm  # or cryptroot
⚙ Decision Point

For the new guide, decide: single NVMe (simpler, laptop-compatible) or dual NVMe with RAID-0 (gentoo-setup.md architecture). The gentoo-setup.md dual-NVMe architecture is the most complete and battle-tested for a desktop Gentoo build with full FDE.

§ 2

RAID Strategy

All three guides take fundamentally different RAID approaches. This choice cascades into bootloader, dracut, and recovery procedures.

arch_hardening_setup.md — LVM RAID-0

LVM's built-in RAID via lvcreate --type raid0. No mdadm. Stripe size 512K for NVMe queue depth.

LUKS containers sit on raw NVMe partitions; LVM is inside LUKS.

arch — LVM RAID-0 inside LUKS
# After LUKS is open on both drives:
pvcreate /dev/mapper/cryptnvme0 /dev/mapper/cryptnvme1
vgcreate vg0 /dev/mapper/cryptnvme0 /dev/mapper/cryptnvme1
lvcreate --type raid0 -L 1T -i 2 \
  --stripesize 512K -n main vg0
lvcreate -L 200G -n secondary vg0
gentoo-setup.md — mdadm RAID-0

Two separate md arrays: md0 for swap, md1 for root. LUKS2 layered on top of md devices. mdadm.conf must be embedded in initramfs. GRUB must preload mdraid1x.

gentoo — mdadm RAID-0 creation
# Zero any existing metadata first
mdadm --zero-superblock /dev/nvme1n1
mdadm --zero-superblock /dev/nvme0n1
wipefs -a /dev/nvme1n1
wipefs -a /dev/nvme0n1

# Swap array (md0)
mdadm --create /dev/md0 --metadata=1.2 \
  --level=0 --raid-devices=2 \
  /dev/nvme1n1p2 /dev/nvme0n1p1

# Root array (md1)
mdadm --create /dev/md1 --metadata=1.2 \
  --level=0 --raid-devices=2 \
  /dev/nvme1n1p3 /dev/nvme0n1p2

# Save mdadm config (embed in initramfs later)
mdadm --detail --scan >> /etc/mdadm.conf
README.md — No RAID

Single nvme0n1p2. No striping. Two mutually exclusive paths: with LVM and without LVM. Neither involves multiple drives. Simplest possible disk layout.

This is the only viable architecture for a single-drive machine.

⚠
RAID 0 has zero redundancy. Any single disk failure destroys all data on both volumes permanently. If targeting RAID-0, the new guide must document off-site backup as a hard requirement, not a footnote.
§ 3

Disk Partitioning

Actual partition commands from each source. The key architectural split is whether /boot lives on a separate unencrypted partition, inside encrypted root, or on the ESP only.

gentoo-setup.md — Dual NVMe with mdadm
nvme1n1 (500 GB — boot disk)
gdisk /dev/nvme1n1
o   # New GPT table

n   # Partition 1 — ESP
    # +512M, type ef00

n   # Partition 2 — swap1 (RAID member)
    # +16384M, type fd00 (Linux RAID)

n   # Partition 3 — root1 (RAID member)
    # remainder, type fd00 (Linux RAID)
nvme0n1 (1 TB — data disk)
gdisk /dev/nvme0n1
n   # Partition 1 — swap2 (RAID member)
    # +16384M, type fd00

n   # Partition 2 — root2 (RAID member)
    # remainder, type fd00
Format ESP
mkfs.vfat -F 32 -n EFI /dev/nvme1n1p1
README.md — Single NVMe
Single drive (with LVM path)
cfdisk /dev/nvme0n1
# nvme0n1p1 → EFI System (~512M)
# nvme0n1p2 → Linux filesystem (rest)

mkfs.vfat -F 32 /dev/nvme0n1p1
ℹ
In README, /boot is mounted from nvme0n1p1 (the unencrypted EFI partition). GRUB never needs to open LUKS. This is the simplest path but leaves the kernel unencrypted.
✦
Boot location decision: gentoo-setup.md places /boot inside the encrypted Btrfs root — this means bootable snapshots include their own matching kernel. README puts /boot on the unencrypted ESP, which is simpler but means snapshot kernels don't travel with the snapshot.
§ 4

LUKS2 & KDF Selection

The KDF choice is constrained by the bootloader. GRUB 2.12 stable only supports PBKDF2 for LUKS2. Argon2id requires a GRUB patch or bypassing GRUB entirely.

⚠
GRUB 2.12 LUKS2 KDF constraint (verified April 2026): GRUB only supports PBKDF2 for partitions it must open. Formatting a GRUB-opened partition with Argon2id will produce: "LUKS2 only supports PBKDF2, Argon2 is not supported" at boot. If GRUB never opens a partition (e.g. swap), Argon2id is fine.
arch_hardening_setup.md — Argon2id (no GRUB)

No GRUB → no KDF constraint. Both drives use Argon2id with high memory cost.

LUKS2 format — Argon2id (Arch)
cryptsetup luksFormat \
  --type luks2 \
  --pbkdf argon2id \
  --pbkdf-memory 1048576 \
  --pbkdf-parallel 4 \
  --iter-time 5000 \
  /dev/nvme0n1p2
gentoo-setup.md — Split KDF

PBKDF2 on root (md1) because GRUB must open it. Argon2id on swap (md0) since GRUB never touches swap. 20+ char passphrase advised to compensate for PBKDF2 GPU weakness.

root12 — PBKDF2 (GRUB constraint)
cryptsetup luksFormat \
  --type luks2 \
  --pbkdf pbkdf2 \
  --iter-time 5000 \
  /dev/md1
swap12 — Argon2id (GRUB never opens this)
cryptsetup luksFormat \
  --type luks2 \
  --pbkdf argon2id \
  --pbkdf-memory 524288 \
  --pbkdf-parallel 4 \
  /dev/md0
Add keyfile as second slot (both volumes)
# Generate 4096-byte keyfile on live host
dd if=/dev/urandom of=/root/luks-keyfile.bin bs=512 count=8

# Add to root12
cryptsetup luksAddKey /dev/md1 /root/luks-keyfile.bin

# Add to swap12
cryptsetup luksAddKey /dev/md0 /root/luks-keyfile.bin

# Backup LUKS headers (CRITICAL)
cryptsetup luksHeaderBackup /dev/md1 \
  --header-backup-file /root/luks-header-md1.img
cryptsetup luksHeaderBackup /dev/md0 \
  --header-backup-file /root/luks-header-md0.img
README.md — Default KDF (implicit)

No explicit --pbkdf flag. Defaults to Argon2id in libcryptsetup ≥ 2.4. No iteration time tuning, no memory cost parameter. No keyfile.

README luksFormat (LVM path)
cryptsetup \
  --cipher aes-xts-plain64 \
  --hash sha512 \
  --use-random \
  --verify-passphrase \
  luksFormat /dev/nvme0n1p2
ℹ
The missing --pbkdf flag means cryptsetup auto-selects Argon2id with its default memory/iteration parameters. This is acceptable but not tuned. The README is the only guide that leaves the KDF implicit.
Recovery: Convert Argon2id keyslot to PBKDF2 (if GRUB fails to boot)
mdadm --assemble --scan
cryptsetup luksConvertKey /dev/md1 --pbkdf pbkdf2
cryptsetup luksDump /dev/md1 | grep PBKDF  # Verify
§ 5

LVM Decision

LVM is used for different purposes in each guide. The gentoo-setup.md deliberately avoids it.

arch_hardening_setup.md

LVM is the RAID mechanism — not for flexible partition sizing. Creates vg0/main (1 TB striped) and vg0/secondary.

gentoo-setup.md

No LVM. LUKS containers sit directly on md devices. Btrfs placed directly on opened LUKS mapper. Simpler stack: mdadm → LUKS2 → Btrfs.

README.md

Both paths shown. LVM path (primary):

README — LVM path
cryptsetup luksOpen /dev/nvme0n1p2 cryptlvm
pvcreate /dev/mapper/cryptlvm
vgcreate vg0 /dev/mapper/cryptlvm
lvcreate -L 16G vg0 -n swap
lvcreate -l 100%FREE vg0 -n root
mkfs.btrfs -f /dev/vg0/root
mkswap /dev/vg0/swap
swapon /dev/vg0/swap

Without-LVM path opens LUKS directly to /dev/mapper/cryptroot.

⚠

gentoo-setup.md — Mount commands (recommended pattern)
Mount all Btrfs subvolumes
umount /mnt/gentoo
mount -o noatime,compress=zstd:3,space_cache=v2,\
  discard=async,subvol=@ \
  /dev/mapper/root12 /mnt/gentoo

mkdir -p /mnt/gentoo/{boot/efi,home,nix,opt,root,srv,tmp,usr/local,var,.snapshots}

mount -o noatime,compress=zstd:3,space_cache=v2,discard=async,subvol=@/.snapshots \
  /dev/mapper/root12 /mnt/gentoo/.snapshots

mount -o noatime,compress=zstd:3,space_cache=v2,discard=async,subvol=@/home \
  /dev/mapper/root12 /mnt/gentoo/home

mount -o noatime,compress=zstd:3,space_cache=v2,discard=async,subvol=@/var \
  /dev/mapper/root12 /mnt/gentoo/var

# @/var gets nodatacow mount option (CoW disabled at FS level too)
mount -o noatime,nodatacow,space_cache=v2,discard=async,subvol=@/var \
  /dev/mapper/root12 /mnt/gentoo/var

mount /dev/nvme1n1p1 /mnt/gentoo/boot/efi
⚙ Subvolume Recommendation for New Guide

Use gentoo-setup.md naming (@/subvol) but adopt README's more granular @/var children. Disable CoW on @/var and all its children via chattr +C before writing any files. Use @/boot/grub2/x86_64-efi as an excluded subvolume if using GRUB with bootable snapshots.

§ 7

Swap & Hibernation

arch_hardening_setup.md — No swap, hibernation disabled

Hibernation is a security threat: images contain decrypted LUKS keys, browser tokens, SSH keys. Blocked at three levels.

Disable hibernation (Arch)
systemctl mask hibernate.target
# + polkit rule denying hibernate
# + no swap LV in LVM layout

Intel TME discussed as cold-boot RAM protection for Suspend-to-RAM.

gentoo-setup.md — ~32 GB encrypted swap, hibernation fully configured
Swap setup (gentoo)
mkswap /dev/mapper/swap12
echo "swap12 UUID=$(cryptsetup luksUUID /dev/md0) \
  /etc/cryptsetup-keys.d/root12.key \
  luks,discard,noauto" >> /etc/crypttab.initramfs

Kernel: CONFIG_HIBERNATION=y. GRUB cmdline: resume=/dev/mapper/swap12. Section 16 dedicated to hibernation.

README.md — 16 GB LVM swap, hibernation implied
Swap setup (README LVM path)
lvcreate -L 16G vg0 -n swap
mkswap /dev/vg0/swap
swapon /dev/vg0/swap

# sysctl tuning
vm.swappiness=35

# NVIDIA hibernation services enabled
systemctl enable \
  nvidia-suspend.service \
  nvidia-resume.service \
  nvidia-hibernate.service

§ 10

Kernel Build & KCFLAGS

All three guides diverge significantly on kernel strategy. The Arch guide uses a pre-built kernel; both Gentoo guides compile from source with very different KCFLAGS.

arch_hardening_setup.md — Pre-built linux-cachyos

No compilation. CachyOS repo provides pre-built kernel with LLVM, LTO, PGO, BOLT, x86-64-v3/v4, and kCFI (Kernel Control Flow Integrity). Pacman hook rebuilds and re-signs UKI on each update.

Install pre-built CachyOS kernel (Arch)
pacman -S linux-cachyos linux-cachyos-headers
gentoo-setup.md — Source, basic LLVM
Kernel packages
emerge sys-kernel/gentoo-sources \
  sys-kernel/linux-firmware \
  sys-kernel/installkernel
eselect kernel set 1
ls -l /usr/src/linux
Configure and build (gentoo-setup)
cd /usr/src/linux
make menuconfig   # Enable: RAID, DM_CRYPT, Btrfs,
                  # NVME, EFI stub, hibernation,
                  # Btrfs POSIX ACL

make -j$(nproc) LLVM=1 \
  KCFLAGS="-O3 -march=native -pipe -flto=thin"

make modules_install
make install  # installkernel runs dracut + grub-mkconfig
README.md — Source, maximum KCFLAGS (Polly + security)
Kernel packages (README adds modprobed-db)
emerge sys-kernel/gentoo-sources \
  sys-kernel/linux-firmware \
  sys-kernel/linux-headers \
  sys-kernel/installkernel \
  sys-kernel/modprobed-db
eselect kernel set 1
nconfig with full KCFLAGS
make nconfig LLVM=1 \
  KCFLAGS="-O3 -march=native -pipe -flto=thin \
  -fno-math-errno -fno-signed-zeros \
  -fno-trapping-math -fcf-protection \
  -D_FORTIFY_SOURCE=3 -D_GLIBCXX_ASSERTIONS \
  -fstack-protector-strong \
  -fstack-clash-protection \
  -fplugin=LLVMPolly.so \
  -mllvm=-polly \
  -mllvm=-polly-vectorizer=stripmine \
  -mllvm=-polly-omp-backend=LLVM \
  -mllvm=-polly-parallel \
  -mllvm=-polly-num-threads=9 \
  -mllvm=-polly-scheduling=dynamic"
Build steps
make -j10 LLVM=1 KCFLAGS="... (same as above)"

make modules_install -j14 LLVM=1 KCFLAGS="..."

make install -j14 LLVM=1 KCFLAGS="..."
# installkernel triggers dracut + grub-mkconfig automatically
★
KCFLAGS security flags in README not in gentoo-setup.md: -fcf-protection (Control Flow Enforcement), -D_FORTIFY_SOURCE=3, -fstack-protector-strong, -fstack-clash-protection, plus the full LLVM Polly vectorizer/parallelizer chain. The README KCFLAGS are the most complete security+performance combination of the two Gentoo source builds.

§ 11

Dracut Configuration

The gentoo-setup.md dracut config is the most complete for RAID+LUKS+keyfile. README has two separate configs. Arch uses uefi="yes" to produce a UKI instead.

⚠
Critical: When using the systemd dracut module, do NOT use rd.luks.key in kernel_cmdline. Use /etc/crypttab.initramfs instead. The gentoo-setup.md explicitly documents this conflict; the README uses rd.luks.uuid directly (the simpler approach that the Gentoo file rejects for good reason).
gentoo-setup.md — RAID + keyfile dracut
/etc/dracut.conf.d/00-gentoo.conf
hostonly="yes"

§ 14

Boot Unlock Mechanism

TPM2+PIN with PCR sealing
Enroll TPM2 with PCR sealing
systemd-cryptenroll \
  --tpm2-device=auto \
  --tpm2-pcrs="0+2+7+12" \
  --tpm2-with-pin=yes \
  /dev/nvme0n1p2

PCRs: firmware code (0), option ROMs (2), Secure Boot state (7), kernel cmdline (12). Recovery key enrolled as fallback. No keyfile.

Keyfile in initramfs (one passphrase prompt total)

GRUB prompts once. dracut then unlocks both LUKS volumes silently via embedded keyfile. systemd-cryptsetup-generator reads /etc/crypttab embedded from crypttab.initramfs.

Boot flow: GRUB → one passphrase → GRUB reads kernel from encrypted Btrfs → dracut → keyfile unlocks both md1 (root) and md0 (swap) silently → systemd init.

Standard passphrase only

No keyfile. No TPM2. No PCR sealing. LUKS UUID referenced by rd.luks.uuid in dracut kernel_cmdline. Passphrase entered at initramfs prompt each boot.

Post-Install Chroot Re-Entry

Only the README documents how to re-enter the chroot after initial install — useful for recovery or continued setup after reboot into live environment.

README — Without LVM chroot re-entry
Re-enter chroot (no LVM)
cryptsetup luksOpen /dev/nvme0n1p2 cryptroot

mount -o noatime,compress=zstd,space_cache=v2,\
  discard=async,subvol=@ \
  /dev/mapper/cryptroot /mnt/gentoo

mount -o noatime,compress=zstd,space_cache=v2,\
  discard=async,subvol=@home \
  /dev/mapper/cryptroot /mnt/gentoo/home

# ... (all other subvols) ...

mount --types proc /proc /mnt/gentoo/proc
mount --rbind /sys /mnt/gentoo/sys
mount --make-rslave /mnt/gentoo/sys
mount --rbind /dev /mnt/gentoo/dev
mount --make-rslave /mnt/gentoo/dev

chroot /mnt/gentoo /bin/bash
source /etc/profile
README — With LVM chroot re-entry
Re-enter chroot (LVM)
cryptsetup luksOpen /dev/nvme0n1p2 cryptlvm

mount -o noatime,compress=zstd,space_cache=v2,\
  discard=async,subvol=@ \
  /dev/vg0/root /mnt/gentoo

mount -o noatime,compress=zstd,space_cache=v2,\
  discard=async,subvol=@home \
  /dev/vg0/root /mnt/gentoo/home

# ... (all other subvols) ...

mount --types proc /proc /mnt/gentoo/proc
mount --rbind /sys /mnt/gentoo/sys
mount --make-rslave /mnt/gentoo/sys
mount --rbind /dev /mnt/gentoo/dev
mount --make-rslave /mnt/gentoo/dev

chroot /mnt/gentoo /bin/bash
source /etc/profile
mount /dev/nvme0n1p1 /boot
swapon /dev/vg0/swap
gentoo-setup.md — Appendix A: Kernel update workflow
Subsequent kernel updates (fully automated with installkernel)
cd /usr/src/linux
cp /boot/config-$(uname -r) .config
make olddefconfig      # accept new options with defaults
make menuconfig        # optional: review new options

make -j$(nproc)
make modules_install

# make install triggers installkernel which:
# 1. Copies kernel to /boot
# 2. Runs dracut --force
# 3. Runs grub-mkconfig
make install

# Optional: manual snapshot before rebooting
snapper -c root create \
  --description "pre kernel $(uname -r) update"
✦

Critical Integration Notes for New Guide

⚠
rd.luks.key vs crypttab.initramfs: When using the systemd dracut module (required for keyfile unlocking), do NOT use rd.luks.key in kernel cmdline — use /etc/crypttab.initramfs instead. This is documented in gentoo-setup.md §11 and is one of the 10 corrections from previous drafts.
⚠
GRUB + Argon2id = boot failure: GRUB 2.12 stable cannot open LUKS2 volumes formatted with Argon2id. Root partition (md1) must be PBKDF2. Swap (md0) can use Argon2id. Recovery: cryptsetup luksConvertKey /dev/md1 --pbkdf pbkdf2.
✦
installkernel + USE="dracut grub" automates the post-build workflow: make install triggers installkernel which runs dracut to build initramfs AND grub-mkconfig automatically. This plus Portage bashrc hooks means kernel updates require only make -j$(nproc) && make modules_install && make install.
✦
/boot inside encrypted root = snapshot-safe kernels: When /boot is a plain directory inside the @ subvolume (gentoo-setup.md architecture), every snapshot captures its own matching kernel and initramfs. Booting a snapshot via grub-btrfs never causes a kernel/modules mismatch.
ℹ
Running system crypttab must have noauto: The runtime /etc/crypttab must have noauto on both LUKS entries. Without it, systemd finds the entries and tries to open already-open devices, causing passphrase prompts mid-boot: sed -i 's/luks,discard$/luks,discard,noauto/' /etc/crypttab
ℹ
@/boot/grub2/x86_64-efi must be excluded from snapshots: GRUB's EFI state must not roll back with the OS snapshot. Create it as a separate Btrfs subvolume so Snapper's snapshot policy excludes it automatically.
★
Snapper /.snapshots subvolume conflict: Creating a snapper config after Btrfs subvolume creation requires removing the auto-created /.snapshots directory and replacing it with a proper mount of the pre-created @/.snapshots (or @snapshots) subvolume. All three guides that use snapper document this cleanup step.
